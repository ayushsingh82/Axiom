DAY 7 — JUN 14 (AFTERNOON): x402 DEEP INTEGRATION
═══════════════════════════════════════════

x402 ON ALL THREE MODALITIES
- /api/x402/image gated behind HTTP 402 — 0.04 USDC per image
- /api/x402/audio gated behind HTTP 402 — 0.005 USDC per TTS call
- All endpoints follow the full probe → 402 → sign → retry flow
- Payment requirements include: USDC address, payTo, facilitatorUrl,
  assetTransferMethod: erc7710, network: eip155:84532

ERC-7715 DELEGATION FLOW
- requestDelegation() calls wallet_grantPermissions via MetaMask Flask
- Grants scoped ERC-20 USDC spend permission (1 USDC cap, 24h expiry)
- Delegation context stored in WalletProvider, attached to all x402 payments
- Session indicator shown in Playground sidebar (active / not granted)

ERC-3009 PAYMENT SIGNING
- signX402Payment() builds TransferWithAuthorization typed message
- EIP-712 domain: USD Coin v2 on Base Sepolia
- 32-byte random nonce, validBefore = now + 1 hour
- Full x402 v2 payload: signature + authorization + delegation context

PLAYGROUND: 4-STEP PAYMENT STATUS UI
During each query, the chat shows exactly what is happening:
  Step 1  requesting  — Calling oracle                   (white dot)
  Step 2  paying      — HTTP 402 received, amount shown  (amber dot)
  Step 3  signing     — ERC-3009 signing in MetaMask     (purple dot)
  Step 4  settling    — Submitting to 1Shot relayer      (green dot)
Each step has an inline detail box showing network, method, cost.

DASHBOARD: ACTIVITY LOG
- logActivity() called on every query (text, image, audio)

DAY 7 — JUN 14 (EVENING/NIGHT): METAMASK INTEGRATION HARDENING
═══════════════════════════════════════════

This was the most technically demanding session — 5 separate bugs fixed
to get MetaMask Smart Accounts working reliably end-to-end.

PROBLEM 1: WRONG WALLET CONNECTING
- Symptom: OKX Wallet, Coinbase Wallet, or any injected provider was
  connecting instead of MetaMask
- Root cause: using window.ethereum grabs the first injected provider,
  not necessarily MetaMask
- Fix: switched to wagmi's metaMask() connector — targets MetaMask
  specifically via EIP-6963 RDNS (io.metamask), ignores all others

PROBLEM 2: AUTHORIZATION ERROR FROM METAMASK SDK
- Symptom: @metamask/sdk threw authorization/CORS errors on connect
- Root cause: SDK adds extra auth layers incompatible with Vercel preview
- Fix: removed MetaMask SDK entirely, switched to pure EIP-6963
  connector (io.metamask RDNS via wagmi) — cleaner, spec-compliant,
  works in both local dev and production

PROBLEM 3: STALE WALLET STATE AFTER ACCOUNT SWITCH
- Symptom: switching MetaMask account did not update the UI
- Fix: added live accountsChanged event listener in WalletProvider
  Auto-signs on connect, updates address reactively

PROBLEM 4: WALLET CONNECTOR ALSO PREFERS FLASK
- WalletProvider now has two-tier connector priority:
  1. io.metamask.flask (MetaMask Flask — supports ERC-7715)
  2. io.metamask (regular MetaMask — x402 only, no delegation)
- Flask badge displayed in Navbar when Flask is the active connector
- isFlask flag exposed throughout the app — controls whether the
  "Grant session" delegation button appears

PROBLEM 5: ERC-7715 DELEGATION FAILING SILENTLY
- Symptom: wallet_grantPermissions was throwing and the error was lost
- Root cause: Flask throws non-standard error shapes
- Fixes applied:
  · extractError() handles: Error object, {message}, {code}, raw string
  · Permission type cascade:
    First tries  erc20-token-transfer  (USDC spend cap)
    Falls back to native-token-transfer (shows Flask dialog anyway)
    Stops immediately on user rejection (code 4001)
  · Inline error shown in Playground sidebar and Dashboard
  · getProvider() two-stage: wagmi connector first, window.ethereum fallback

PROBLEM 6: IMAGE SERVER TIMEOUT
- Symptom: server tried to fetch Venice image and timed out at 10s
- Fix: return Pollinations URL to client; browser loads image directly

RAIL LINE OVERLAP AT LAPTOP WIDTH
- Symptom: vertical decorative rails at 12% from each edge were
  overlapping with content on 1280px (laptop) screens
- Root cause: 12% of 1280px = 153px from edge, but max-w-5xl content
  has only 128px margin — rails crept 25px inside the content area
- Fix: changed rail position from 12% to 8% (gives 102px on 1280px,
  comfortably within the 128px margin)
- Also raised visibility breakpoint from sm (640px+) to lg (1024px+)
  in both RailLines.tsx and page.tsx — rails completely hidden on
  tablets and phones where they would always overlap
